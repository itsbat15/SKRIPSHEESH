# 3.3 Prosedur

Subbab ini menjelaskan langkah kerja yang detail untuk setiap tahapan dalam siklus pengembangan prototipe sistem informasi ARTHA. Prosedur pengembangan prototipe disajikan pada sembilan sub-subbab berikut.

## 3.3.1 Requirements

Tahap kebutuhan berfokus pada penggalian masalah dan kebutuhan operasional di delapan kantor cabang Bimbel ARTHA. Pengumpulan data dilakukan melalui wawancara bersama Pemilik Lembaga dan Staf Administrasi Cabang, disertai observasi langsung terhadap dokumen pencatatan fisik seperti buku besar pendaftaran dan lembar rekapitulasi harian kas. Seluruh temuan kebutuhan pengguna kemudian dipetakan ke dalam *User Stories* yang dilengkapi dengan *acceptance criteria*. Skala prioritas pengerjaan fitur ditentukan berdasarkan *customer business value* dan ketergantungan antarmodul, untuk memastikan pendaftaran siswa terselesaikan terlebih dahulu sebelum modul pelaporan lanjutan.

## 3.3.2 Planning

Tahap perencanaan bertujuan menyusun rencana kerja pengembangan perangkat lunak secara realistis. Setiap *User Story* yang telah disusun pada tahap kebutuhan diberikan estimasi bobot menggunakan *Story Points*. Keterkaitan antarmodul dipetakan secara terstruktur untuk menentukan urutan modul yang harus dibangun lebih awal. Seluruh beban kerja kemudian dialokasikan ke dalam perencanaan iterasi sebagai target acuan jadwal penyelesaian prototipe.

## 3.3.3 Iteration Initialization

Tahap inisialisasi iterasi menandai dimulainya satu siklus pengembangan spesifik. Pengembang menyiapkan konfigurasi repositori Git dengan strategi *branch* yang teratur, instalasi Next.js dan Laravel, serta persiapan *database* MySQL. Pada tahap ini, sekumpulan *User Stories* dengan prioritas tertinggi untuk iterasi dipilih untuk memastikan fokus pengerjaan perangkat lunak terarah.

## 3.3.4 Design

Tahap perancangan menerjemahkan kebutuhan fungsional menjadi *blueprint* sebelum kode program dibuat. Pemodelan proses bisnis usulan (*To-Be*) dirancang untuk menggambarkan alur interaksi operasional antarpengguna. Kebutuhan fungsional dan alur interaksi pengguna dengan perangkat lunak dimodelkan menggunakan *Use Case Diagram* serta *Activity Diagram*. Struktur data relasional dirancang menggunakan *Entity Relationship Diagram* (ERD) lengkap dengan spesifikasi data di MySQL. Selain itu, tahap ini mencakup penerapan arsitektur sistem serta rancangan antarmuka pengguna dalam bentuk *wireframe low-fidelity*.

## 3.3.5 Implementation

Tahap implementasi menerapkan siklus berulang antara *Unit Testing*, *Code*, dan *Refactor*. Pengembang melakukan pengujian fungsi unit kode secara langsung untuk memvalidasi logika perhitungan dan pembatasan hak akses cabang. Pengembangan antarmuka web dibangun menggunakan Next.js App Router dan Tailwind CSS, pengembangan API *backend* dibangun menggunakan Laravel RESTful API, serta pengelolaan basis data relasional dikelola melalui migrasi MySQL. Setelah fitur berhasil lolos pengujian fungsi, *refactoring* dilakukan untuk merapikan kode program yang duplikat dan mengoptimasi kinerja algoritma tanpa mengubah fungsional sistem.

## 3.3.6 System Testing

Pengujian fungsionalitas antarmuka dan alur transaksi dilakukan menggunakan metode *Black Box Testing* dengan skenario uji coba positif maupun negatif. Pengujian integrasi antarmuka Next.js dengan server Laravel API melalui otentikasi token Sanctum dievaluasi untuk memastikan tidak terjadi kebocoran data antarcabang. Seluruh bug yang ditemukan selama pengujian dicatat pada log pengujian untuk segera diperbaiki sebelum siklus iterasi ditutup.

## 3.3.7 Retrospective

Tahap retrospeksi berfungsi sebagai evaluasi penutup dari setiap siklus iterasi yang telah selesai dijalankan. Pengembang meninjau tingkat ketercapaian *Story Points* yang berhasil diselesaikan dibandingkan dengan target awal perencanaan. Prototipe fungsional hasil iterasi didemonstrasikan kepada Pemilik Lembaga dan perwakilan Staf Administrasi Cabang untuk memperoleh umpan balik secara langsung. Evaluasi retrospeksi menentukan keputusan apakah sistem masih memerlukan iterasi perbaikan lanjutan, atau telah siap ke tahap validasi penerimaan akhir.

## 3.3.8 User Acceptance Testing

Pengujian penerimaan pengguna dilaksanakan setelah seluruh siklus iterasi PxP dan seluruh fungsionalitas utama selesai dijalankan. Pengujian ini melibatkan Pemilik Lembaga dan staf administrasi dari cabang sebagai pengguna akhir sistem. Instrumen pengujian menggunakan Lembar Skenario Uji Fungsional (*UAT Test Cases Checklist*) yang mencakup uji operasional modul pendaftaran, pembayaran, penjadwalan, dan rekonsiliasi kas. Pelaksanaan UAT difokuskan pada pengisian *checklist* fungsional dan diselesaikan dengan penandatanganan Berita Acara Penerimaan Sistem (*Sign-Off*) sebagai bukti formal bahwa prototipe telah disetujui dan memenuhi kebutuhan operasional mitra.

## 3.3.9 Deployment

Tahap *deployment* merupakan langkah finalisasi teknis untuk mempublikasikan prototipe aplikasi web. *Frontend* Next.js di-*deploy* ke platform Vercel untuk memanfaatkan otomatisasi CI/CD repositori Git. Dari sisi *backend*, Laravel API dan *database* MySQL di-*deploy* ke Cloud Hostinger yang dikonfigurasi dengan *web server* Nginx dan proteksi sertifikat keamanan HTTPS SSL. Pengujian kemudian dilakukan dari delapan kantor cabang untuk memastikan sistem dapat diakses secara stabil dan bersamaan.
